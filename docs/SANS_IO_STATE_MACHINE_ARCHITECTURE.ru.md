# 🏛️ Архитектура Sans-I/O State Machine: Как проектировать торговые движки и сетевые протоколы без боли, флакающих тестов и гонок данных

*Глубокий технический разбор архитектурного паттерна Sans-I/O (Sans-Input/Output): почему в квант-стратегиях и низкоуровневых протоколах не должно быть сокетов, таймеров и асинхронных вызовов.*

---

## 📌 Введение: Анатомия типичной катастрофы

Большинство разработчиков при создании первого торгового бота или сетевого клиента совершают одну и ту же архитектурную ошибку: **смешивают бизнес-логику принятия решений с вводом-выводом (I/O) и системными вызовами**.

Типичный код выглядит примерно так:
```python
# ❌ Классический антипаттерн: логика намертво завязана на сокеты и время
async def on_market_tick(ws, tick):
    if time.time() - last_order_time > 1.0:
        if tick.bid_price > current_quote:
            await ws.send_json({"type": "cancel", "id": active_order_id})
            await ws.send_json({"type": "new_order", "price": tick.bid_price})
```

На первый взгляд код кажется простым и понятным. Но по мере усложнения системы на продакшене начинаются кошмары:
1. **Неуловимые гонки данных (Heisenbugs):** Пока корутина ждала `await ws.send_json()`, с биржи прилетел отчет об исполнении (Fill) или новый тик стакана. Состояние ордеров рассинхронизировалось, и система начинает дублировать заявки.
2. **Мучительное тестирование:** Чтобы протестировать стратегию, приходится поднимать мок-серверы на локальных портах, создавать фейковые WebSocket-соединения и вставлять `asyncio.sleep()` в надежде поймать тайминги. Тесты идут минутами, периодически «флакают» в CI из-за загрузки процессора.
3. **Привязка к транспорту (Transport Lock-in):** Когда потребуется перейти с WebSocket на Unix Domain Sockets, Kernel-Bypass DPDK или Lock-Free Shared Memory, вам придется **переписать всю стратегию с нуля**, потому что весь код пронизан вызовами `ws.send()`, `async/await` и `time.time()`.
4. **Невозможность детерминированного воспроизведения (Replay):** Если на реальных торгах произошел баг, воспроизвести его по логам невозможно: в коде используются вызовы часов ядра (`time.time()`), которые в повторном прогоне вернут совершенно другое время.

Решением всех этих проблем является паттерн **Sans-I/O (Sans-Input/Output State Machine)**.

## 💡 Что такое Sans-I/O?

Термин **Sans-I/O** (от французского *sans* — «без») зародился в сообществах разработчиков высоконагруженных протоколов (проекты `h11`, `wsproto`, `quiche`, `sans-io`).

> **Фундаментальное правило Sans-I/O:**
> Ядро протокола и логика принятия решений представляют собой **чистую детерминированную машину состояний (Pure State Machine)**. В ней **НЕТ сокетов, НЕТ системных часов, НЕТ потоков и НЕТ `await` / `async`**.

### 📐 Каноническая математическая модель (Автомат Мили / Mealy State Machine)

В терминах теории автоматов, **Sans-I/O** представляет собой детерминированный конечный преобразователь (Finite State Transducer), где функция перехода и генерации команд строго чистая:

$$
(S_{t+1}, \mathbf{C}_t) = \delta(S_t, E_t, \tau_t)
$$

где:
- $S_t \in \mathcal{S}$ — текущее внутреннее состояние стратегии (активные ордера, позиция, кэш котировок);
- $E_t \in \mathcal{E}$ — дискретное входящее событие ($\mathrm{Top\text{-}of\text{-}Book}$, $\mathrm{OrderAck}$, $\mathrm{Fill}$, $\mathrm{TimerTick}$);
- $\tau_t \in \mathbb{N}$ — монотонная отметка времени ($\mathrm{now\_ns}$), передаваемая вызывающим контекстом;
- $\mathbf{C}_t \subseteq \mathcal{C}$ — кортеж сгенерированных исходящих команд ($\mathrm{NewOrder}$, $\mathrm{CancelOrder}$, $\mathrm{StopQuoting}$);
- $S_{t+1} \in \mathcal{S}$ — новое состояние системы на шаге $t+1$.

## 🏗️ Разделение ответственности: WHAT vs HOW

В архитектуре Sans-I/O система делится на два изолированных мира:

| Слой | Назначение | Примеры в коде | Что содержит |
|---|---|---|---|
| **State Machine Core (Логика)** | Определяет **ЧТО** делать (*WHAT*) | [`python/mmclient/strategy.py`](../python/mmclient/strategy.py), [`NativeMarketMaker`](../cpp/include/mm/strategy_native.hpp) | Расчет цен, инвентарный риск, жизненный цикл ордеров, проверка монотонности `seq` |
| **Transport Adapters (Ввод-вывод)** | Определяет **КАК** передавать данные (*HOW*) | [`ws_picows.py`](../python/mmclient/ws_picows.py), [`ws_naive.py`](../python/mmclient/ws_naive.py), [`shm_ipc.py`](../python/mmclient/shm_ipc.py) | Сокеты, `asyncio`, `uvloop`, `epoll`, `mmap`, сериализация JSON/SBE |

## 🔍 Разбор реализации в нашем проекте

Рассмотрим реализацию маркет-мейкинг стратегии в файле [`python/mmclient/strategy.py`](../python/mmclient/strategy.py).

### 1. Состояния ордеров без флагов и булевых переменных
Вместо набора разрозненных флагов `is_pending`, `is_cancelled`, создается строгий конечный автомат:

```python
class OState(Enum):
    PENDING_NEW = auto()     # Ордер отправлен, ждем подтверждения биржи
    LIVE = auto()            # Подтвержден, стоит в стакане
    PENDING_CANCEL = auto()  # Отправлен запрос на отмену, ждем ответа
```
> Ордер в состоянии `PENDING_NEW` или `PENDING_CANCEL` запрещает стратегии слать повторные заявки. Это на 100% исключает шторм дублирующих ордеров при задержках на бирже.

### 2. Чистая обработка тика стакана (`on_tob`)
Метод [`on_tob`](../python/mmclient/strategy.py#L215) принимает срез стакана и отметку времени:

```python
def on_tob(self, tob: Tob, now_ns: int) -> list[Cmd]:
    # 1. Проверка сессионных счетчиков (монотонность)
    if tob.md_seq < self._md_seq:
        return [StopQuoting(f"md_seq decreased: {self._md_seq} -> {tob.md_seq}")]
    
    self._last_tob_ns = now_ns
    if tob.md_seq == self._md_seq:
        return []  # Стакан не изменился: ответом является тишина

    self._md_seq = tob.md_seq
    self._bid_px = tob.bid_px
    self._ask_px = tob.ask_px

    # 2. Генерация команд на котирование
    return [
        *self._quote(_BID, tob.bid_px, tob.ask_px, tob.bid_px, tob.md_seq),
        *self._quote(_ASK, tob.ask_px, tob.ask_px, tob.bid_px, tob.md_seq),
    ]
```
Обратите внимание:
- Внутри метода **нет ни одного `await` или `socket.send`**;
- Метод возвращает `list[Cmd]`. Вся ответственность за отправку лежит на транспорте.

### 3. Чистая детекция зависания фида (`on_timer`)
Как защититься от зависшего соединения без привязки к таймерам ОС? Через метод [`on_timer`](../python/mmclient/strategy.py#L173):

```python
def on_timer(self, now_ns: int) -> list[Cmd]:
    if self._swept or self._last_tob_ns is None:
        return []
    
    age = now_ns - self._last_tob_ns
    if age <= self.stale_ns:
        return []

    # Фид завис: останавливаем торговлю и генерируем отмену всех активных заявок
    self._stopped = True
    self._swept = True
    resting = [o for o in self._orders.values() if o.state in (OState.PENDING_NEW, OState.LIVE)]
    return [
        StopQuoting(f"stale feed: {age} ns since last book"),
        *[SendCmd(CancelOrder(cl_id=o.cl_id)) for o in resting]
    ]
```

## 🚀 5 Главных преимуществ Sans-I/O на практике

### 1. ⚡ Мгновенные детерминированные тесты (586 тестов за 3.6 секунды!)
Поскольку у стратегии нет сокетов и реального времени, в тестах не нужно запускать сервер и ждать секундами:
- Мы можем подать на вход `on_tob` миллион тиков подряд в цикле `for`;
- Можем сгенерировать любые сценарии гонок: «пришел Fill до OrderAck», «пропущен номер seq», «стакан скрестился», «сервер завис на 10 секунд»;
- **Все 586 тестов выполняются за 3.6 секунды с 100% покрытием строк и веток**.

### 2. 🔄 Бесшовная замена транспорта: от WebSocket до Shared Memory
Благодаря Sans-I/O мы смогли подключить **один и тот же класс `Strategy`** сразу к двум кардинально разным транспортам:
1. **WebSocket (`ws_picows.py`):** Адаптер вычитывает JSON из WebSocket и вызывает `strategy.on_tob(tob, now_ns)`.
2. **Lock-Free Shared Memory IPC (`shm_ipc.py`):** Адаптер читает бинарные 64-байтные SBE структуры из `mmap` и вызывает тот же самый `strategy.on_tob(tob, now_ns)`.
> Логика стратегии **не изменилась ни на одну строчку кода**, а задержка системы упала с **202.3 µs до 2.10 µs (ускорение в 96× раз)**!

### 3. ⏱️ 100% Детерминированный Replay и Time-Travel Debugging
Если на продакшене произошел сбой, вам достаточно сохранить входной лог тиков и отчетов. Запустив `Strategy` с теми же входными данными и метками времени, вы гарантированно получите **бит-в-бит идентичную последовательность решений**.

### 4. 🛡️ Полное устранение Heisenbugs и блокировок
Вся стратегия выполняется строго синхронно в одном потоке. Никаких мьютексов, семафоров и асинхронных состояний гонки внутри квант-логики.

### 5. 🎯 Изолированное измерение производительности (Pure Benchmarking)
Мы можем точно измерить чистую задержку вычислений стратегии (вплоть до наносекунд) без шума сети, буферов ядра ОС и задержек TCP-стека.

## 📋 Чек-лист: Как проверить, что ваш код соответствует Sans-I/O

- [x] В модуле стратегии нет импортов `socket`, `asyncio`, `websockets`, `aiohttp`, `requests`.
- [x] В методах стратегии нет ни одного `await` или блокирующего `send()`.
- [x] В коде нет прямых вызовов `time.time()`, `time.monotonic()`, `datetime.now()` (время всегда передается в аргументах метода).
- [x] Все методы возвращают команды или события наружу, а не выполняют побочные эффекты I/O.
- [x] Модуль можно на 100% протестировать без поднятия сетевых сокетов и без моков транспорта.
